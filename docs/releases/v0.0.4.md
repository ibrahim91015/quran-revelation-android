# Quran Revelation v0.0.4

This release adds clearer sajdah cues, optional pauses after sajdah, and a beta translation-only picture-in-picture window. It merges 17 upstream commits through **6a999e5dc**, preserving the fork's reciters, revelation playback, app identity and navigation features. [Upstream review](../upstream/2026-10-31.md).

## Sajdah sound, alert and pause

In **Settings**, the audio section now contains:

| Setting | Behavior | Default |
| --- | --- | --- |
| Sajdah sound and alert | Play the chime and show a visual alert after a sajdah ayah finishes. | On |
| Sajdah chime | Tap a choice to preview; save to use it. Six original sounds are bundled offline. | Soft bells |
| Sajdah chime volume | Horizontal slider controlling chime gain relative to media volume. Preview before saving. | 50% |
| Test sajdah sound | Play the saved chime and gain without sending a notification. | Preview only |
| Pause after sajdah | Off, 2 seconds, 5 seconds, Until I resume, or Custom (0–60 seconds). | 2 seconds |

The six options are **Soft bells**, **Warm marimba**, **Gentle harp**, **Crystal chime**, **Evening glow**, and **Peaceful rise**. They last 2.8–3.1 seconds, with gentle attacks/releases and no external sound downloads. The fork generates these original assets from its included script; they contain no sampled recordings.

The chime uses Android's **media** stream, so vibrate/ringer mode does not mute it. It never changes Android's volume, takes audio focus, or stops the recitation. Muted media and system rules that block media still apply. The slider changes only chime gain, not recitation volume.

Android receives a separate **Sajdah alerts** channel at high importance (the highest normal alert level), with no channel sound or vibration. The media chime supplies the sound. Notification permission and the user's Android channel/system settings govern whether a visual or heads-up alert appears. No full-screen notification is requested.

The alert remains through the **next recited ayah** and disappears when that ayah finishes. This follows the listening order: after 96:19, a revelation session keeps the alert through 68:1. Basmala playback does not expire it early. Stopping, seeking, replacing the session, or turning off sound-and-alert clears it.

The pause setting works independently of the sound-and-alert toggle. Timed pauses resume the existing session; **Until I resume** waits for an app, notification, or media Play command. Custom zero disables the pause. Manually pausing, stopping, or browsing elsewhere cancels a pending automatic resume. Resuming does not replay the sajdah cue or skip the next ayah. The persistent media notification remains available.

## Translation picture-in-picture (Beta)

Enable **Settings → Translation picture-in-picture (Beta)**. It defaults to off. While recitation is playing, leaving the reader or picker for Home opens Android's horizontal PiP window. It shows the current ayah's translation and a small surah:ayah reference (for example **2:113**) in the bottom corner:

- Uses one installed translation, with the same active-choice and priority ordering as translation mode. An empty selection uses the first installed translation, matching the reader's fallback.
- Updates with the service's playing ayah, including revelation-order transitions.
- Fits the complete text without ellipsis and reflows when resized. Long translations necessarily use smaller text; enlarging the window helps.
- **Translation PiP appearance**, immediately below the beta toggle, offers centered or justified text and a preferred maximum size (14–48 sp; default 32 sp). Auto-fit always stays on, so a larger preference never clips a long translation. Colors follow the app's light/dark theme; Arabic and dyslexia-friendly translation fonts follow the reader's font rules.
- Expanding restores the app. Closing/dismissing PiP leaves audio playing through the existing background service.
- Shows a clear message if no translation is installed/selected or the ayah's translation is unavailable. It does not invent or download translation text.

PiP needs Android 8.0+ and device/system support. Internal app navigation should not open PiP. Android owns the window's close, expand, resize and media controls. The feature remains beta pending broader physical-device testing.
