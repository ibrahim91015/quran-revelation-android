# Quran Revelation v0.0.3

This release fixes index lists jumping to the latest reading page and introduces predictable tab navigation and protected audio-session handoffs. It uses this fork's own version number, independent of the upstream Quran for Android version.

## Opening the app and using tabs

- With a live playing or paused recitation, reopening the app returns directly to its current ayah and original playback order. Opening the reader does not resume a paused recitation. Media-notification taps use the same location.
- Without a recitation, a warm reopen returns to the picker tab and scroll position you left. A fresh process or a quit task uses the first tab in your saved order (the leftmost tab in English). Each tab keeps its own saved position.
- Switching tabs, including by swiping, starts the destination tab at its top. Tapping the selected tab also returns to its top.
- Double-tapping the recitation's originating tab scrolls to its current surah. The relevant row has a subtle green marker while playing or paused. Other tabs do not inherit that marker or audio-scroll behavior.
- Hold a tab and drag it horizontally onto another tab to reorder it. The order is saved. Accessibility actions also allow moving a tab left or right.

The jump was caused by each list's resume handler independently scrolling to the latest reading page. Those jumps are removed, and list positions are stored under stable tab identities instead of shared view hierarchy state.

## Browsing during recitation

Opening another surah or Juz location pauses the current recitation and leaves you at the location you selected. The old recitation's tracking updates no longer pull the reader back. Selecting the green current-surah row keeps the existing session and opens its current ayah.

If browsing paused the old recitation, pressing Play at the new location asks before replacing it. The dialog identifies the previous surah, ayah, and revelation/standard order. **Cancel** keeps the old session paused; **Stop previous and play** starts the selected recitation. The warning covers both the bottom audio control and ayah-specific playback.

A recitation paused manually can be replaced without a warning by default. Enable **Settings → Confirm replacing paused recitation** to also ask for manually paused sessions. This setting defaults to off. The picker and notification can still resume the old session; returning to it does not resume it automatically.

Late seek/completion callbacks cannot restart a session after a browsing pause. A Material 3 theme override used by the reader on Android 10+ is corrected so its confirmation dialog has the required theme attributes.

## Independent versioning and upgrades

- App version / release tag: **0.0.3 / v0.0.3**.
- Android internal version code: **4,000,003**, above the legacy `3651002` code, so installation upgrades existing copies in place.
- Application ID and signing key remain unchanged: `com.ibrahim91015.quran.revelation`.
- Upstream source base remains documented separately: Quran for Android `3.6.5`, snapshot `cd6a99ed096ea1ec8dc1b1f99364244b05001bdd`.
- Legacy `3.6.5-revelation.*` releases and tags remain available so existing links keep working. New releases use this fork's `v0.0.x` sequence.

Install the new signed APK over the existing clone to retain its settings, bookmarks, and downloads. It continues to install alongside the original Quran for Android.

## Verification and limits

The attached validation report records regression tests, Android 16 playback/navigation tests, release lint, signing, and APK checksums. New coverage includes independent list offsets, warm returns, tab switching and reordering, source-specific green markers/double taps, background return to a paused ayah, cancel/confirm behavior, and the manual-pause warning preference. Existing MP3/Opus, offline, screen-off, short-surah-tail, and coexistence checks remain in the suite.

Device automation uses a dedicated Android 16 emulator. Fresh physical-phone validation remains necessary, especially for device-specific background restrictions. Active sessions survive leaving the interface; automatic recovery after force-stop, reboot, or process death is not added by this update. Original-app private downloads remain subject to Android's storage restrictions; accessible folder imports are unchanged.
